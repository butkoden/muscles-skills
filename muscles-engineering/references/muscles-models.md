# Модели данных Muscles

Применяй при создании, использовании или исследовании `muscles.Model` и `Column`, контрактов API и сопоставления моделей с SQL. Ниже — наблюдения о локальном Muscles 1.0.0rc5 и текущем `muscles-data-sql`, а не гарантия для других версий. Сначала проверь используемые зависимости, исходники и тесты проекта.

## Источники

- Пакет `muscles`, модуль `muscles/core/schema/` — конструирование, преобразование и проверка значений.
- `muscles/tests/schema/` и `muscles/docs/schema.md` — примеры и тесты. При расхождении проверь исполняемое поведение.
- Тесты пакета `muscles-asgi` — примеры `JsonRequestBody` и `JsonResponseBody`.
- Исходники и тесты `muscles-data-sql` — преобразование в таблицу и работа с данными.

## Объявление и значения

`Model` описывает поля и данные; `Column` задаёт тип и свойства. Пример:

```python
from muscles import Column, Enum, Integer, Model, String

class Product(Model):
    name = Column(String, nullable=False, min_length=2, max_length=100)
    quantity = Column(Integer, default=0)
    status = Column(Enum(enum=["draft", "active"]), default="draft")

product = Product(name="Книга", quantity=3)
product.quantity = 5
```

Проверь поведение конкретного типа и его `setstate`/`getstate`: некоторые значения преобразуются или вызывают исключение при присваивании. `default` может быть вызываемым; момент его применения зависит от пути создания и чтения. `UUID4` в этой версии поддерживает `default="gen"`. `nullable=False`, `min_length` и `max_length` учитываются при валидации; `title`, `description`, `example` служат метаданными. Не считай `primary_key`, `unique`, `index` реальными ограничениями базы без проверки слоя хранения и миграций.

## Валидация и сериализация

Явно вызывай `model.validate()` и при `False` анализируй `model.errors()`; отдельно обрабатывай исключения, возможные при создании или присваивании. Типы и преобразования полей не гарантируют одинакового поведения. Для недоверенного ввода проверяй фактические требования к отсутствующим и пустым значениям, формат ошибок и границы типов.

В локальной версии `Column.validate` проверяет `required` условием `self.required and self.value is not None`; не считай `required=True` надёжной проверкой обязательного поля без проверки версии и теста. Локальный эксперимент также показал сохранение ошибок между последовательно проверенными экземплярами: проверь независимость экземпляров и повторную валидацию, если результат используется для принятия решений. Сообщай об этом как о наблюдении данной реализации, а не свойствах всех версий.

`as_dict(exclude_fields=[...])` возвращает значения с преобразованием полей; `to_json()` в этой реализации возвращает словарь, а ненулевые значения переводит в строки, не создавая JSON-строку; `dump()` описывает схему. Проверь конкретные типы, исключение конфиденциальных полей и сериализацию JSON отдельно. Не предполагай, что DTO API и модель хранения должны совпадать.

## API и OpenAPI

`JsonRequestBody(model=...)` и `JsonResponseBody(model=...)` могут описывать модели в метаданных `RestApi`. На основе тестов версии проверяй форму `request=[...]` и `response={код: ...}`. Метаданные схемы сами по себе не доказывают runtime-валидацию, авторизацию или соответствие ответов: тестируй реальные запросы, ошибки и OpenAPI. Если у создания и ответа разные поля, используй отдельные модели по существующим соглашениям проекта.

## SQL и границы преобразования

`Model` не создаёт таблицу и не сохраняет экземпляры. `muscles_data_sql.map_model` строит SQLAlchemy `Table` из полей `Column`; это не ORM-маппинг экземпляров. В текущем коде учитываются простые типы, `primary_key`, `nullable` и автоинкремент; неизвестные типы преобразуются в `String`, обходятся атрибуты непосредственно в `model_cls.__dict__`, а `unique`, индексы, defaults и внешние ключи автоматически не переносятся. Не теряй ограничения молча: проверяй полученную таблицу, используй явную SQLAlchemy-схему и миграции, если необходимы связи или дополнительные ограничения.

`SqlRepository` работает с сессией и таблицей и возвращает отображения строк, а не экземпляры `Model`; `UnitOfWork` управляет commit/rollback и закрытием сессии. Это API extra `legacy`, которому необходим SQLAlchemy. Для изменений БД используй предусмотренные проектом миграции, а не полагайся на изменение класса. `muscles-data` предоставляет реестр и контракты миграций, но не является ORM; конкретное выполнение зависит от backend. Подробности сверяй с документацией и исходниками версий установленных пакетов.
